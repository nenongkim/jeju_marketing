# 실제 사용자 평가 진행 절차

현재 상태: 미실시. 이 문서는 평가 계획이며 사용자 수·만족도·매출 효과를 증명하지 않는다.

안내 기준: 2026-10-28 공개 배포 소스 `43b17db`. [참여자에게 보낼 안내문](참여자_안내문.md)을 전달한다. 비공개 저장소 권한이 없는 참여자에게는 파일 내용과 회신 양식을 메시지로 복사해서 보낸다. 저장소 초대는 필요하지 않다.

## 모집과 준비

구좌 음식점 운영자 또는 마케팅 담당자를 우선 모집한다. 가능하면 3명부터 5명까지 진행하되 실제 참여 인원만 보고한다. 학생·지인은 별도로 분류한다. 참여자에게 목적과 약 25분 소요, 중단 가능 여부를 설명하고 기록 동의를 확인한다. 이름·전화번호·매장 매출 원장은 기록하지 않고 P01 같은 식별자를 사용한다. 녹음·공개 인용은 별도로 동의를 받는다.

진행자는 브라우저를 열어 데이터가 정상 표시되는지 확인하고, 기존 연습 계획을 실제 평가 결과와 혼동하지 않도록 참여자마다 별도 브라우저 프로필을 사용한다. 공개 링크는 https://nenongkim.github.io/jeju-marketing-demo/ 이며 수집일 2026-10-27 자료를 사용한다. 참여 직전 실제 배포 버전은 [release.json](https://nenongkim.github.io/jeju-marketing-demo/release.json)의 source_commit으로 확인하여 기록한다. 평가 중 버전이 바뀌면 별도 집단으로 구분한다. 시크릿 창을 쓴 경우 창을 닫기 전에 반드시 결과를 내보낸다. 평가자 설명과 기능 오류를 모두 기록한다.

## 과제와 측정

1. 참여자의 역할·운영 경험·데이터 도구 사용 경험을 기록한다. 처음 화면을 보여주기 전 평소 계획 방법을 질문한다. 동의를 받기 전 녹음이나 평가 기록을 시작하지 않는다.
2. 로그인 과제를 별도로 확인한다: 사업체 운영자 → 계정 정보 채우기 → 로그인. 로그인 성공 여부·소요 시간·도움을 기록하되 핵심 과제 10분에는 포함하지 않는다. 실제 계정이 아닌 공개 시연 계정임을 설명한다.
3. 참여자 안내문의 핵심 과제 1부터 5까지를 동일하게 제공한다. 과제: “구좌 음식점의 2026년 12월 마케팅을 검토하세요. 고객군과 시간 구간을 선택한 이유, 실행 전에 확인할 사항을 적고 계획을 저장한 다음 일정과 저장 근거를 확인하여 전체 계획·기록을 내보내세요. 정답 고객군은 없습니다.” 안내문을 읽고 시작에 동의한 시점부터 JSON 파일 또는 전체 JSON 내용 확인까지 시간을 잰다. 10분이면 종료한다.
4. 12월 선택, 고객군 비교, 최근 동기간·시간 구간 확인, 근거 작성, 계획 저장, 일정·저장 근거 확인, 전체 내보내기를 각각 기록한다. 동일하게 제공한 안내문 읽기는 도움 횟수에 포함하지 않는다. 진행자의 추가 힌트·대신 조작은 시각과 내용을 적고 도움으로 분류한다. 원격 단독 평가에서 관찰하지 못한 내용은 ‘참여자 자기보고’ 또는 ‘미확인’으로 표시한다.
5. 핵심 과제 후 계획 수정·저장, 실행 기록 작성·저장, 실행 결과 조회, 마지막 JSON 내보내기를 추가로 확인한다. 이 시간은 따로 기록한다. 실제 홍보를 하지 않았다면 ‘미착수’를 유지하고 실제 실행일·활동·반응 수는 빈칸으로 둔다. 평가용 클릭이나 계획 저장을 마케팅 실행·사업 효과로 계산하지 않는다. 핵심 과제를 실패해 진행자가 저장을 도왔다면 추가 과제도 ‘도움 후 진행’으로 기록한다.
6. 아래 해석 질문 4개를 묻는다. 참여자 안내문에는 채점 답안을 넣지 않는다. 처음 답변을 그대로 적은 뒤에만 정답을 설명한다. 질문을 하지 않았다면 0점 대신 미측정으로 둔다. 계획 근거는 계절성·고객군·최근 동기간 범위를 각각 올바르게 사용하면 항목당 1점, 총 3점으로 기록한다. 광고 효과가 입증되었다고 쓴 경우 별도 오해로 기록한다.
7. 이해 용이성과 실무 유용성을 각각 1점부터 5점까지 묻고 이유를 기록한다. 실제 채택은 미결정/검토 예정/계획에 반영/실행 완료로 구분한다. 평가 과제에서 만든 계획·기록과 실제 업무 채택을 분리한다. 실패·중단·부정적 의견도 기록한다.

## 받을 자료와 확인 방법

- 최종 `구좌_계획과실행기록.json` 또는 전체 JSON 텍스트: 12월·선택 고객군·계획·저장 근거·마지막 기록이 맞는지 확인한다. ‘저장 근거 보기’나 계획 화면의 내보내기만 받으면 최종 실행 기록이 빠질 수 있으므로 **전체 계획·기록 내보내기** 결과를 받는다.
- 참여자 회신과 일정 또는 실행 결과 캡처: 익명 ID로 연결한다. 캡처 불가 시 화면·버튼·현상을 적은 설명을 받는다. 파일 미제출을 과제 성공으로 추정하지 않는다.
- 자동 전송 기능이 없으므로 안내를 보낸 대화방 등으로 직접 받는다. 파일 수신 여부와 누락 사유를 개별 기록에 적는다. JSON의 `user_evaluation: null`과 `revenue_effect: null`은 정상이며 실제 평가 결과는 별도 양식에 기록한다.
- 기존 계획이 섞인 경우 참여자에게 평가용 계획을 식별해달라고 요청한다. 다른 사람의 계획을 삭제하거나 평가 자료에 포함하지 않는다.

## 시간 절감 비교를 주장하려면

이번 기본 평가는 도구 사용성만 측정한다. 시간 절감률을 주장하려면 별도 비교를 사전에 설계한다. 동일한 원천 수치가 담긴 정적 표와 프로토타입을 비교하고, 참여자별 순서를 번갈아 배정한다. 12월과 3월의 동일 구조 과제를 교차 배정하며 동일한 제한시간·도움 규칙을 적용한다. 표 준비 시간 포함 여부를 사전 기록한다. 월별 난이도와 반복 학습, 소수 편의표본의 한계를 보고하고 전후 차이를 인과 효과로 단정하지 않는다. 비교를 하지 않았다면 시간 절감은 미측정으로 둔다.

## 정리

[개별 기록](개별_평가기록_양식.md)을 참여자마다 복사하고 [결과 집계](결과_집계_양식.md)에 옮긴다. 실제 기록은 동의 범위를 확인한 뒤 저장하며 원본 서명·연락처는 Git에 넣지 않는다. 실패·부정적 의견도 포함한다. 기능 시험 기록을 실제 사용자 평가에 넣지 않는다. 매출·고객 증가 효과는 별도 실행 및 비교 관측 없이는 미측정으로 유지한다.
