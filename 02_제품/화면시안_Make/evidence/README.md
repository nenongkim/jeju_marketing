# 구좌 음식점 통합 프로토타입

실제 데이터 분석 → 계획 작성 → 일정 → 실행 기록을 동일한 계획 ID로 연결한다. Make와 이전 HTML 시안의 진입 주소 모두 이 화면으로 이동한다. 기존 인공 예시·가상 성과·임시 로그인 화면은 활성 동선에서 제거했다. 과거 assets는 이력 보존용이며 현재 진입 화면이 로딩하지 않는다.

## 실행과 지원 범위

저장소 최상위에서 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1`로 실행한다. 기본 주소는 `http://127.0.0.1:8766/화면시안_Make/evidence/index.html`이다. Pages는 수동 실행만 가능하다.

지원 범위는 구좌읍·음식점업·2026년 12개 월·3개 고객군이다. 계절성은 2023년부터 2025년까지, 최근 비교는 2025·2026년 1월부터 8월까지다. 대상 월과 다른 날짜로 계획을 저장하거나 내보낼 수 없다. 실제 실행일은 미래 날짜를 허용하지 않으며 준비 일정과 구별한다.

## 저장과 실행 기록

- 월·고객군을 확인하고 선택 이유·실행안·날짜·성과 지표를 입력해 저장하면 일정에 나타난다.
- 같은 월에도 새 계획을 여러 개 작성할 수 있다. 계획 수정은 ID와 기존 실행 기록을 유지한다.
- 계획마다 저장 당시 데이터 근거를 보관한다. 새 데이터와 자동으로 섞지 않는다.
- 실행 상태·실제 실행일·활동·시간·클릭·예약·쿠폰·측정 조건을 직접 기록한다. 빈 숫자는 null이며 확인된 0과 다르다.
- 실행 완료는 날짜와 활동 내용이 필요하다. 기록은 사용자 입력이며 검증된 마케팅 효과로 표시하지 않는다.
- 전체 계획·기록 내보내기 및 개별 저장 근거 보기에서 JSON을 제공한다. 다운로드가 안 되면 화면 JSON을 복사할 수 있다.
- 계획 삭제는 두 번 확인하며 해당 실행 기록도 함께 삭제한다. 필요한 내용은 먼저 내보낸다.

저장은 현재 브라우저 localStorage의 `ijto-gujwa-workspace-v1`에 한정된다. 로그인·서버 저장·기기 간 동기화는 없다. 이전 예시 서비스와 사례의 저장 내용은 자동 가져오지 않고 원래 키에 보존한다. 손상된 저장 데이터를 발견하면 덮어쓰기를 중지한다. 저장 실패 시 입력과 기존 상태를 유지한다. 미저장 계획·실행 기록은 메뉴 이동 시 메모리에 유지하며 입력 중 새로고침·페이지 이탈은 브라우저 경고를 요청한다. 브라우저가 경고를 생략하거나 사용자가 이탈을 선택하면 미저장 입력은 사라질 수 있으므로 저장 후 이동한다. 수정 계획별 초안은 같은 월의 다른 계획과 분리한다. 계획 수정 시 최초 저장한 분석 근거와 실행 기록을 유지한다. 저장 근거 보기는 다운로드하지 않으며 전체 내보내기는 저장 완료된 값만 포함한다. 뒤로가기·앞으로가기는 메뉴 이동 이력을 따른다.
