# 제주 관광 데이터 활용 공모전 전체 작업 요약

작성일: 2026년 10월 28일, 한국 시간

이 문서는 데이터 확보부터 분석, 프로토타입 구현, 제출 초안, 공개 배포까지 이번 대화에서 진행한 작업을 요약한다. 데이터 수집·분석의 기준일은 2026년 10월 27일이며, 10월 28일에는 자동 배포 연결과 전체 작업 정리를 진행했다. 모든 작업을 10월 28일에 새로 수행했다는 뜻은 아니다.

현재 결과물은 **구좌 음식점의 마케팅 계획을 실제 지역 통계로 검토하고, 계획·일정·실행 기록을 연결한 평가용 프로토타입**이다. 실제 사업자 평가, 업무시간 절감, 매출 증가 효과는 아직 측정하지 않았다.

## 4. 분석 방법과 주요 결과

### 계절성과 비수기 안정성

43개 읍면동의 12개월, 총 516개 조합을 비교했다. 2023년부터 2025년까지 각 연도의 월 관측값을 연평균과 비교하고, 달력 일수로 보정한 일평균 지수도 계산했다. 각 연도 평균을 1로 두는 계절지수이며 전년 대비 증감률이 아니다.

구좌 12월의 3개 연도 평균 방문 일평균 지수는 **0.760**, 음식점 소비 일평균 지수는 **0.819**였다. 세 해 모두 두 지수가 연평균보다 낮았으며, 기준값 0.90·0.95·1.00에서도 낮은 수요로 분류됐다.

### 규칙의 비교와 한계

2023·2024년 자료로 2025년을 비교했다. 실제 낮은 수요는 해당 연도 방문·소비 일평균 지수가 모두 1 미만인 182건으로 정의했다.

| 규칙 | 선정 후보 | 실제 낮음 | 후보 적중 비율 | 낮은 사례 발견 비율 |
| --- | ---: | ---: | ---: | ---: |
| 전년도 두 지수 1 미만 | 188 | 106 | 56.38% | 58.24% |
| 전년도 두 지수 0.95 이하 | 83 | 51 | 61.45% | 28.02% |
| 2개 연도 반복 및 평균 0.95 이하 | 65 | 44 | 67.69% | 24.18% |

보수적 규칙은 선정 후보의 적중 비율이 높지만 많은 낮은 수요 사례를 놓친다. 평가 연도가 하나이고 현재 개정 자료를 사용했으므로 미래 예측 정확도나 마케팅 성공률로 표현하지 않았다. 현재 화면의 3개 연도 반복 조건과 비교 실험의 2개 연도 조건도 구분했다.

### 구좌의 최근 동기간 변화

방문·소비·시간대 자료가 모두 관측된 2025년과 2026년 각각 1월부터 8월까지 비교했다.

| 지표 | 2025년 | 2026년 | 증감률 |
| --- | ---: | ---: | ---: |
| 방문 집계 | 4,713,366명 | 4,573,686명 | −2.96% |
| 음식점 소비 | 45,370,183,178원 | 43,269,525,794원 | −4.63% |
| 카드 이용건수 | 1,402,422건 | 1,313,471건 | −6.34% |

동기간 고객군별 음식점 소비는 내국인 관광객 −12.37%, 도민 +0.87%, 외국인 관광객 +67.82%였다. 외국인은 전년 규모가 작아 증가율만으로 마케팅 우선순위를 정하지 않는다.

2025년 12월 소비 구성은 내국인 관광객 67.04%, 도민 24.78%, 외국인 관광객 8.18%였다. 최근 동기간 변화와 과거 12월 구성은 다른 기간의 정보로 구분했다. 2026년 12월 실적이나 매출 예측은 만들지 않았다.

### 시간대와 장소 후보

시간대는 24시간 분포와 새벽·아침·점심·오후·저녁·야간의 6개 구간으로 비교했다. 구좌 12월 내국인 관광객은 점심 구간에 소비금액 46.03%, 이용건수 50.43%가 관측됐다. 이는 광고·할인 최적 시간의 검증 결과가 아니다.

12개월·3개 고객군·24개 시간대의 864칸 중 미관측 49칸은 null로 유지했다. 미관측을 0건으로 채우지 않았다. 시간대와 지역별 원천의 최근 48개 비교 조합은 금액 최대 6원, 건수 최대 7건 차이가 있어 원본을 유지하고 한계를 표시했다.

구좌 12월의 같은 월 3개 연도 관광객 차량 도착 기준 후보는 비자림, 스누피가든, 김녕해수욕장, 용눈이오름, 김녕미로공원이다. 거리·현재 영업·제휴·최적 동선이나 고객군별 방문 장소를 검증한 것은 아니다.

## 5. 프로토타입 구현과 통합

초기에는 기존 예시 화면과 실제 데이터 사례가 별도로 존재했다. 이후 두 기존 진입 화면을 실제 구좌 통합본으로 연결하고, 인공 예시 수치·가상 성과·임시 로그인을 활성 동선에서 제거했다. 이전 파일과 저장 내용은 이력으로 보존하되 자동 가져오지 않는다.

현재 지원 범위는 구좌읍 음식점업, 2026년 12개 월과 3개 고객군이다.

1. **분석:** 계절성·연도별 반복·고객 구성·동기간 변화·시간대·장소 후보·출처·한계를 확인
2. **계획 작성:** 선택 이유, 실행안, 대상 월의 날짜, 확인할 성과 지표 입력
3. **일정:** 같은 계획 ID로 저장·수정·삭제하고 저장 당시 분석 근거 보관
4. **실행 기록:** 진행 상태, 실제 실행일, 활동, 작성 시간, 클릭·예약·쿠폰 수, 측정 조건 기록
5. **내보내기:** 전체 저장 계획·기록 또는 현재 초안을 JSON으로 확인하고 파일 저장 요청

계획과 실행 기록은 현재 브라우저 localStorage에만 저장한다. 계정 인증, 서버 저장, 기기 간 동기화, 광고 실행, 평가 결과 자동 수집은 구현 범위에 포함하지 않는다. 빈 수치와 확인된 0건을 구분하며, 사용자가 입력한 실행 완료를 검증된 사업 효과로 간주하지 않는다.

## 6. 점검에서 수정한 문제

- 메뉴 이동 중 미저장 실행 기록이 사라지는 문제 수정
- 같은 달의 서로 다른 계획 사이에서 수정 초안이 섞이지 않도록 분리
- 계획 수정 시 저장 당시 분석 근거와 기존 실행 기록 유지
- 새 계획에 이전 계획의 내용이 남는 문제 수정
- 저장 후 편집 상태와 안내 문구 정리
- 저장 근거 조회와 파일 내보내기 동작 분리
- 뒤로가기·앞으로가기와 메뉴 이동 연결
- 대상 월과 다른 준비 날짜, 잘못된 날짜, 음수·소수 건수 등 오류 차단
- 저장 실패 시 기존 상태 보존, 손상된 저장 데이터 덮어쓰기 차단
- 미저장 입력이 있을 때 브라우저 이탈 경고 요청

36개 월·고객군 조합 표시와 계획 작성·수정·일정·실행 기록·새로고침 복원·JSON·삭제를 확인했다. 동일 월 복수 계획의 입력 분리, 미저장 기록 복원, 상세 근거 펼치기도 점검했다. 검증용 계획과 기록은 브라우저에서 삭제했다.

## 7. 공모전 제출 초안과 사용자 평가 준비

공고문과 참가서식 1번부터 5번까지 검토했다. 분석 범위를 넓히기보다 실제 활용 증빙을 보완하는 것이 우선이라고 판단했다.

- 개인·팀용 신청서 항목에 맞춘 **3페이지 PDF 초안** 작성
- 분석표·출처·화면·검증·평가 보완란을 담은 **서식 5 증빙 4페이지** 작성
- HWP로 옮길 수 있는 텍스트 편집 원고 제공
- 7개 PDF 페이지의 한글·표·그림·서명란 표시 확인
- 인적사항과 서명은 직접 작성할 자리로 남김
- 사용자 평가·시간 절감·매출 효과는 미측정으로 구분

초안은 [제출 폴더](../00_제출/20261027_공모전초안)에 있다. 원본 HWP를 수정한 파일은 아니며 최종 양식으로 옮긴 뒤 분량과 항목을 다시 확인해야 한다. 10월 28일 신청서와 서식 5를 통합 프로토타입·공개 시연 링크 기준으로 갱신했다. 공개 배포 화면을 반영하고 신청서 3페이지·서식 5 4페이지를 재검증했다.

실제 평가를 위해 [진행 절차](../06_증빙/사용자평가/평가_진행절차.md), [개별 기록 양식](../06_증빙/사용자평가/개별_평가기록_양식.md), [집계 양식](../06_증빙/사용자평가/결과_집계_양식.md)을 마련했다. 실제 운영자 여부, 과제 완료, 시간, 도움 횟수, 해석 정확도, 계획 반영과 의견을 기록한다.

## 8. 로컬 실행과 공개 배포

- 원본 비공개 저장소: https://github.com/nenongkim/jeju_marketing
- 평가용 공개 저장소: https://github.com/nenongkim/jeju-marketing-demo
- 평가 사이트: https://nenongkim.github.io/jeju-marketing-demo/
- 로컬 실행: 저장소 루트의 `start-local.ps1`

복사된 Pages 워크플로는 다른 사람의 서버가 아니라 현재 저장소의 Pages 설정을 찾다가 실패한 것이었다. 푸시 자동 실행을 중지하고 로컬 실행을 정리했다. 이후 현재 요금제에서 비공개 저장소의 Pages를 지원하지 않는 것을 API로 확인해, 사용자 계정의 별도 공개 저장소에 필요한 화면과 집계 자료만 게시했다.

공개 주소에서 파일 7개의 내용 일치, 월·고객군 선택, 계획 저장·수정, 실행 기록, 새로고침 복원, JSON의 0/null 구분을 확인했다. 사이트는 로그인 없이 접속 가능하다. 평가자의 입력은 서버로 자동 전송되지 않으므로 평가 종료 후 내보낸 파일과 별도 평가 양식을 받아야 한다.

배포 근거: [공개 배포 검증](../06_증빙/ijto_20261027/public_deployment.json).

### 10월 28일 자동 동기화 연결

원본 main의 지정된 프로토타입 파일을 수정하고 푸시하면 데이터 검사와 공개 경계 검사를 거쳐 평가용 저장소로 동기화하도록 구성했다. 공개 대상으로 지정된 파일은 다음 7개다.

`index.html`, `case.css`, `case.js`, `workflow.js`, `recent.js`, `case-data.json`, `recent-data.json`

공개 배포용 `.nojekyll`, 안내 README, 게시 버전을 표시하는 `release.json`은 별도로 생성한다. 신청서·원본 CSV·사용자 평가 기록·비공개 저장소 이력 전체는 복사하지 않는다. 테스트에서도 가상의 신청서·원본·평가·환경설정 파일이 공개 폴더에 포함되지 않는지 확인했다. 평가용 저장소에만 쓸 수 있는 SSH 배포 키를 사용하고 개인키는 Actions 암호화 비밀값으로 보관한다. 이 문서에는 인증정보를 기록하지 않는다.

자동 동기화 실검증 결과: **성공**. 원본 커밋 `be43dda2e1fd4abc2e8eeadd054149bb9162f1df`의 [Actions 실행](https://github.com/nenongkim/jeju_marketing/actions/runs/40527692532)이 성공했고, 공개 저장소 커밋 `4dc32f02b4dccd01607fff651e7c766b749af566`의 Pages 빌드도 완료됐다. 공개 사이트의 `release.json`과 배포 파일 7개의 내용이 원본과 일치하는지 확인했다.

설정: [자동 동기화 워크플로](../.github/workflows/sync-demo.yml), [허용 목록 복사 스크립트](../.github/scripts/publish_demo.py).

## 9. 현재 남은 일과 해석 한계

- 실제 사용자 평가와 계획 채택 근거 확보: 사용자 진행 예정
- 업무시간 절감·매출·광고 효과: 미측정, 비교 관측 없이 효과 수치 작성하지 않음
- 모바일 실기기와 실제 파일 다운로드 완료: 별도 확인 필요. 화면 JSON 대안은 검증됨
- 원천별 이용허락 표시와 파생 통계 공개 조건의 미확인 사항: 기존 출처 목록의 확인 과제로 유지. 배포 성공이 이용조건 검토 완료를 뜻하지 않음
- 최종 참가자 정보·서명·서식 3·4와 제출 ZIP 준비
- 통합 화면과 공개 URL 반영 완료. 실제 평가 후 실측 기록을 증빙에 추가

지역 방문 집계는 매장 고객 수가 아니고, 카드 이용건수는 고유 고객 수가 아니다. 음식점 전체 소비는 특정 카페 매출이 아니다. 분석·프로토타입 구현 완료와 실제 현장 성과를 계속 구분한다.
